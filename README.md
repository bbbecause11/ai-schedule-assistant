# 🗂️ AI 智能日程收纳 & 日历导入工具

> 把散落在聊天记录、课表截图、备忘录里的碎片化日程，一键整理成可视化日程表，
> 并导出为标准 `.ics` 日历文件，直接导入手机、电脑、Outlook、Google 日历。

由 **DeepSeek-V4.1-Flash** 模型在 **WorkBuddy 工作台** 构建，基于 Streamlit，单文件应用，可本地一键运行。当前版本 **v2.11.0**。

**仓库地址**：<https://github.com/bbbecause11/ai-schedule-assistant>（公开，可直接访问）

| --- | --- | --- |
| 本地运行 | <http://localhost:8502> | `streamlit run app.py --server.port 8502`（8501 已被本机其他项目占用） |
| 云端部署 | 见「部署 → 方案 B」 | Streamlit Community Cloud，可生成公网分享链接 |

### 双引擎解析设计

这是本项目与普通"调一次大模型"的方案最大的区别：

```
              ┌──────────────────┐
   文本/图片 ─→│  OCR（本地内存）  │─┐
              └──────────────────┘ │
                                   ├─→ ┌──────────────┐   融合   ┌────────────┐
              ┌──────────────────┐ │   │ 本地规则引擎  │───┬───→│ 去重/冲突  │─→ 日程表
   纯文本 ───→│  清洗 & 分段      │─┘   └──────────────┘   │    │ 过期过滤   │
              └──────────────────┘     ┌──────────────┐   │    └────────────┘
                                       │ 大模型解析(可选)│───┘
                                       └──────────────┘
```

- **有 API Key**：大模型负责理解口语化、上下文依赖强的文本（如群聊记录），规则引擎负责补全字段与校验。
- **没有 API Key / 网络异常**：自动降级为纯本地规则引擎，**完全离线可用**，比赛现场不会"空场"。
- **大模型超时或报错**：捕获异常 → 展示原因 → 自动回退规则引擎，页面不崩溃。

### 加载动画：为什么不用 st.spinner

OCR 一张课表要几秒、AI 请求可能十几秒。这段时间里如果页面什么都不显示，
用户会以为网站卡死了。本项目用**自定义转圈胶囊**（顶部居中 + 品牌渐变进度光带 +
进度文案），实测踩过几个坑，都固化进了 `selfcheck.py`：

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| `st.spinner` 在阻塞期间**不显示** | 同步阻塞时 spinner 压根不推到前端 | 改用自定义 HTML 元素 |
| 依赖 JS 定时器 | Streamlit 每次 rerun 重建 DOM，定时器被打断，动画卡在某一帧 | 动画必须用纯 CSS `@keyframes` |
| 指示器画在 `st.tabs` 里 | tab 内元素阻塞时不推前端，用户看不见 | 指示器画在**主区域（tabs 之外）** |
| 指示器用普通流式布局 | 用户点了页面下方的按钮、页面已滚下去，卡片停在视口外 | 卡片**固定定位**在视口顶部居中 |

## 🚀 快速开始

### 环境要求

- Python **3.10+**（推荐 3.11 / 3.12 / 3.13）
- 可联网（仅安装依赖时需要；运行时可完全离线）

> **关于 OCR 依赖的版本差异**（这点很容易踩坑，已在 `requirements.txt` 中自动处理）：
> - Python **< 3.13**：安装 `rapidocr-onnxruntime`（自带 onnxruntime）
> - Python **≥ 3.13**：安装 `rapidocr` + **额外显式安装 `onnxruntime`**
>
> 如果只装 `rapidocr` 而漏了 `onnxruntime`，运行时才会报 `onnxruntime is not installed`。
> 侧边栏会实时显示 OCR 是否就绪；即使完全没装，文本解析功能也不受影响。

## 🔑 配置大模型（可选，但推荐演示时配置）

支持任意 **OpenAI 兼容接口**：DeepSeek、通义千问、Kimi、智谱 GLM、OpenAI 等。
**代码中不存在任何硬编码密钥**。

### 方式一：侧边栏「🤖 AI 接口」小窗口（最省事）

点侧边栏最上方的 **「🔑 AI 接口」** 按钮，弹出一个小窗口，直接填：

| 字段 | 说明 | 留空时 |
| --- | --- | --- |
| **服务商** | 下拉选厂家，**选完自动填好下面的地址和模型名**；默认是「-」（未选择） | 用 DeepSeek 默认地址 |
| **API Key** | 大模型密钥，输入框是密码框，页面上显示圆点 | 无法启用 AI |

| **模型名** | 模型标识 | 用 `deepseek-chat` |

> 💡 顺序是「先服务商 → 再密钥」：先确定用哪家，才知道去哪个平台申请 Key。
> 三个输入框的空状态统一显示为「-」，「服务商」选了「-」时地址和模型名会一起清空，

窗口里还有三个按钮：**「保存并启用」**、**「测试连接」**（真发一次请求，确认密钥/地址/模型都对）、**「清除」**。

> 🔒 **密钥安全**：只存在浏览器的**页面内存**里，刷新页面即失效；
> 不写文件、不进日志、不回显完整密钥（侧边栏只显示 `sk-t••••••••cdef` 这样的掩码）。
> 部署给他人使用时，请改用下面的环境变量方式。

### 接口地址怎么填？

**规则只有一条：填到「兼容层」为止，程序会自动接上 `/chat/completions`。**

程序实际请求的地址是 `{你填的地址}/chat/completions`，所以：

- ✅ `https://api.deepseek.com/v1` → 请求 `https://api.deepseek.com/v1/chat/completions`
- ❌ `https://api.deepseek.com/v1/chat/completions` → 会拼成 `.../chat/completions/chat/completions`，404

各家的地址都不一样，**后缀最容易漏**，所以推荐直接用上面的「服务商」下拉：

## 🔐 记住这台设备（可选配置 `[crypto] cookie_key`）

侧边栏「🔑 AI 接口」弹窗里勾选「记住这台设备（180 天）」后，API Key / 接口地址 /
模型名会用 **Fernet 对称加密**成一段密文，存进用户自己的浏览器 Cookie：

- 浏览器里拿到的是密文，看不到明文 Key
- 有效期 180 天，换设备 / 清 Cookie 后需重填（想要跨设备请见文末「后续规划」）
- 「清除」按钮会同时清掉内存配置和 Cookie
- 读取用 Streamlit 原生 `st.context.cookies`（服务端直接读，无第三方组件、无闪烁）

加密密钥来源（按优先级）：

1. `st.secrets` 里的 `[crypto] cookie_key`（推荐显式配置）：

```toml
[crypto]
cookie_key = "随便一串足够长的随机字符"
```

2. 没配置时自动从已有的 `[smtp] password` 派生（无需额外配置；换邮箱授权码会让
   旧 Cookie 失效，用户重填一次即可）
3. 两者都没有（纯本地裸跑）→ 功能静默降级为「不记住」

### 课表截图识别（v1.4.0 新增）

直接把教务系统导出的课表截图整张丢进来就行，不需要裁剪。程序会先判断「这是不是一张课表」，
是的话不走逐行文本解析，而是**把表格结构还原出来**，再按「星期 + 节次」逐节生成日程。

| 环节 | 做法 |
| --- | --- |
| 判断是不是课表 | 同一水平行上找出 ≥5 个「星期X」表头，且左侧有 ≥3 个节次编号；不满足就退回普通文本解析，聊天截图不会被误判 |
| 列边界 | 按相邻表头中心点取中值切分，容忍表头被 OCR 粘成「节次 星期一」 |
| 行边界 | 按相邻节次**编号中心点**取中值切分（用编号顶边会让整列内容串到上一节） |
| 单元格 | 每列内按纵向间距聚类：同一格的多行文字贴得很近，两门课之间至少隔小半个行高 |
| 跨节合并 | 一格写一次（真合并单元格）与逐节重复写（第 1、2 节各写一遍）两种排版都支持 |
| 一格两门课 | 按「/」拆开，同一门课重复写的自动去重 |

解析出来的每一条都带：星期、第几节（换算成具体时刻）、课程名、教师、地点、周次、单双周。
时间按内置默认作息表推算（第 1 节 08:00 起、每节 45 分钟），所以全部标记为**待核对**。

> **日期对不对，取决于「学期第 1 周的周一」**。程序默认把本周当成第 1 周，
> 想对齐真实上课日期，去左侧 **⚙️ 设置与外观 → 📅 课表识别** 填上学期的第一个周一，
> 再重新解析一次即可。

识别效果的量化验证：内置 4 张合成课表（教务系统风 / 无外框极简风 / 带底纹表头 / 手机小图）
共 33 门课，**命中 33/33、星期 33/33、节次 33/33、课程名 33/33、地点 33/33、周次 33/33**。

打磨中固化的规则（全部来自真实语料暴露的问题）：

1. **分号 = 事件分隔符**：用户粘贴的日程经常是一行里用「；」串起全天

2. **车次防误判**：「计算机楼C102」「实验楼D区」也会命中车次正则——

3. **「，地点」后缀收编**：行尾「，XX」是用户手写地点的最可靠信号，
   优先于关键词提取，并从行里剥掉防止混进标题；祈使句（「务必到场」）排除。
4. **地点词位置约束**：标题里的地点词（「图书馆自习」「实验室例会」）不能剥——
   关键词命中必须位于最后一个逗号之后，逗号后没有再回退。
5. **动词前缀判定**：「参观实验室」「修改论文」是日程名不是地点——
   关键词吞掉动词前缀时整段返回标题。

### 自定义作息表：让「第X节」变成准确时间（v1.9.0，v2.4.0 重做编辑器）

课表上写的是「第6-7节」「晚修」这类**相对节次**，不同学校的作息完全不同。
现在可以在 **⚙️ 设置与外观 → ⏰ 作息时间表** 里编辑一张自己的作息表：

- 内置 12 节通用模板，直接在上面改，不用从零开始填；
- 点侧边栏入口弹出**独立编辑窗口**（桌面约 1200px 宽，手机几乎满屏），三列一目了然；
- **时间用选择器挑，不用手打**：`st.time_input` 在手机上会直接调出系统时间面板；
- 改完**立即生效**，无需保存；可「＋ 添加一节」「✕ 删除某节」「恢复默认模板」。

> **为什么 v2.4.0 把编辑器换掉了？**
> 旧版用 `st.data_editor` 表格，在 `num_rows="dynamic"`（可增删行）模式下，
> Streamlit 会把**完整数据**算进组件的元素 ID —— 一旦你的编辑让数据变了，
> 元素 ID 就变，前端刚提交的编辑被当成新组件丢弃。
> 表现出来就是「输入新时间 → 回车 → 退回原来的值 → 再输一遍才保存」。
> 现在改用 `st.text_input` + `st.time_input`：每个控件有稳定的 key，
> 值由 session_state 保管，不存在元素 ID 漂移，输入即时生效。
>
> 附带还修了：深色主题下时间框是白底黑字（Streamlit 1.66 的时间显示值是
> `div` 而非 `input`，之前的着色规则没覆盖到）。

**换算规则（按优先级）**：

| 图片里写了 | 结果 |
| --- | --- |
| `14:50`（绝对时间） | 直接用，**不查表** |
| `第6-7节` | 第 6 节的**开始** ~ 第 7 节的**结束**（例：14:50-16:25） |
| `晚修` / `早读`（自定义名称） | 查表里同名行，整段时间 |
| `第12节`（表里没有） | 标记**待确认时间**，绝不瞎猜；提示去设置里补充 |

**「10:45 第3-4节」这种混杂写法**：开始用绝对时间 10:45，结束用第 4 节的下课
时间补齐 —— 绝对时间永远优先，两者不冲突。

**AI 路径同样生效**：发请求时会把作息表注入提示词——

```
【作息表】用户学校的作息表如下（必须用它换算，不许用你记忆里的时间）：
第1节 08:00-08:45；第2节 08:55-09:40；…；晚修 19:00-21:30
```

并要求模型：节次必须查表、查不到就留空标待确认、不许编默认时间。

验证：3 张节次型截图（第1-2节 / 6-7节 / 12节 / 绝对时间混杂 / 晚修别名）
**6/6 通过**；全部 6 条解析路径（课表网格 / 时间块 / 逐行 / AI）统一走同一张表。

### 教务课表单元格：一门课 = 课程名 + (节次)周次 + 字段列表（v1.8.0）

教务系统（强智 / 正方 / 青果）的课表单元格长这样：

```
高等数学D
(3-4节)3-18周/校区:回龙校区/场地:回龙1303(多)/教师:徐秀丽/
课程性质简称:必修/选课备注:/学分:4.0/重修标记:
```

这里的「/」**既分隔字段，也可能分隔课程**。旧实现一律按「/」切开，
结果「场地:回龙1303」「教师」「必修」全被当成独立的课程，
日程标题就成了「场地:回龙1414(多)」——这正是用户截图里的现象。

现在的规则：**以「课程名 + (节次)周次」为条目边界**，其后的字段
（校区/场地/教师/课程性质/选课备注/学分/重修标记）全部归属这个条目：

| 内容 | 去向 |
| --- | --- |
| 课程名（第一个非字段段） | 标题 |
| 场地 | 地点（校区并入括号后缀） |
| 教师 | 备注 + 教师字段（支持「陈盈诺,刘永晋」多人） |
| 课程性质 / 学分 / 选课备注 / 重修标记 | 备注 |
| (3-4节) | 节次 → 换算成具体上课时间 |
| 3-18周 / 3-7,10-12,15-18周 / 第1周 | 周次 → RRULE 的 COUNT |
| (单) / (双) | 单双周 → RRULE 的 INTERVAL=2 |

同一格里上下排多门课（江大周四 6-7 节就是「职业生涯发展与规划」两个时段 +
「体育与健康1」）也能逐条拆开，各自的地点 / 教师 / 周次不会串。

- 中文词内空格：「回龙校 区」「重修标 记」→ 合并回去
- 「教师 :徐秀丽」冒号前的空格

### 重复规则：图片里写了什么，导出就是什么（v1.7.0）

**优先级只有一条：图片解析出的规则 > 网站设置。** 网站里那套「是否重复 / 频率 / 次数」
只用于你事后点开某一条日程去手动纠正，**不参与解析生成**，也不会拿默认值去覆盖图片。

| 图片上的写法 | 导出的 RRULE |
| --- | --- |
| 每周四 · 共16次 | `FREQ=WEEKLY;BYDAY=TH;COUNT=16` |
| 每周一，1-5周 | `FREQ=WEEKLY;BYDAY=MO;COUNT=5` |
| 第1-16周 | `FREQ=WEEKLY;COUNT=16` |
| 1-16周 单周 / 双周 | `FREQ=WEEKLY;INTERVAL=2;COUNT=8` |
| 单双周交替 / 隔周 | `FREQ=WEEKLY;INTERVAL=2` |
| 周一至周五 / 工作日 | `FREQ=WEEKLY;BYDAY=MO,TU,WE,TH,FR` |
| 每周一三五 | `FREQ=WEEKLY;BYDAY=MO,WE,FR` |
| 每两周的周三 | `FREQ=WEEKLY;INTERVAL=2;BYDAY=WE` |
| 每天 · 共30次 | `FREQ=DAILY;COUNT=30` |
| 每月 | `FREQ=MONTHLY` |
| 没有任何重复描述 | 不写 RRULE，按单次事件导出 |

几个容易踩的细节：

- **「每每周四」这种叠字**：OCR 常把「每」读出两遍，已归一化。
- **不连续周次**（`2-6,9-18`）：RRULE 会一路排下去，所以额外写 `EXDATE`
  把中间的空档周排掉，否则日历里会凭空多出两次课。
- **单双周要对齐到第几周**：表头的「第 44 周」是偶数周，上面挂的「单周」课会顺延一周开始，
  「双周」课本週就上——不然两门课会挤在同一周。
- **只有频率没有次数**（比如只写「每周四」）：RRULE 里就**不带 COUNT**，
  不虚构 16 次；导出 .ics 时用 `UNTIL` 给一个结束条件，避免变成永久重复。

> 同一张截图里，一门课的场地、教师、课程性质都归到**同一条日程**上，
> 重复规则也只有这一条主日程带，不会让地点/属性各自带一套 RRULE。

### 字段列表型截图：按时间块归并（v1.6.0）

除了「网格课表」，还有一类更常见的截图：**左边一列时间、右边一张卡片，卡片里逐行列字段**——

```
10:45
场地：回龙2311(多)
校区：回龙
教师：张伟
课程性质简称：必修
选课备注：
重修标：
每周四 · 共 16 次
```

如果按「一行一条」解析，一门课会被拆成 7 条日程，标题还会变成「场地：回龙2311」。
所以这类结构会先做**时间块归并**：

| 规则 | 说明 |
| --- | --- |
| 切块 | 遇到 `10:45` 或 `第1-2节` 就开新块，之后的行都归这一块，直到下一个时间节点 |
| 主标题 | 块内第一个「非属性」的行；找不到就用「10:45 日程」兜底，**绝不拿场地/教师/必修当标题** |
| 属性黑名单 | 场地、校区、教室、教师、课程性质、选课备注、重修标、学分、学时、教学班，以及单独成行的地点/人名/必修 |
| 字段映射 | 场地 → 地点；校区 → 并入地点；教师/课程性质/学分 → 备注；「每周四 共16次」→ 循环规则 + 备注 |
| 触发门槛 | 全文至少 2 行命中字段前缀，普通备忘、聊天记录、车票完全不受影响 |

字段行的三种写法都认：`场地：回龙2311(多)`、`场地  回龙2311(多)`、`场地回龙2311(多)`
（OCR 经常把冒号和空格一起吞掉）。

### 追加 vs 清空：两个清空按钮的区别

本工具默认**追加式录入**：每次点「✨ 开始解析」，结果都接在已有日程后面，不会覆盖。
所以「开始新一份日程」之前要先清空，两个按钮各管一半，别拿错：

| 按钮 | 位置 | 清掉什么 | 不清什么 |
| --- | --- | --- | --- |
| **🧹 清空文本框** | 录入页 | 左侧文字、已上传的截图 | **已录入的日程全部保留** |
| **🗑️ 清空全部日程** | 录入页 / 日程表页 / 侧边栏 | 一条不剩：日程、解析报告、输入框文字、已选图片 | — |

两个按钮都是**两段式确认**：第一次点击只会亮出黄色的确认条，再点「确定清空」才真正执行，
演示时手滑也不会把数据抹掉。

> 为什么清空还要连输入框和图片一起清？因为文本框和上传控件会保留上一次的内容，
> 只清日程的话，再点一次解析就会把旧文本 / 旧截图重新识别一遍，日程又「长」回来了。

### 配色体系：一套令牌，两套主题

界面所有颜色都来自 CSS 变量（design tokens），写在 `_TOKENS_LIGHT` / `_TOKENS_DARK` 两个字典里，
由 `_css_tokens()` 按当前主题注入 `:root`。样式表里**不允许出现散落的颜色字面量**
（唯一例外是品牌渐变上的白色高光），`selfcheck.py` 的 K 组会自动拦截。

| 令牌分组 | 作用范围 |
| --- | --- |
| `ink / ink-2 / ink-3 / muted / muted-2 / muted-3` | 正文、标题、次要文字、占位说明 |
| `brand-1..4 / brand-grad / brand-glow` | ins 品牌渐变、主按钮、选中态 Tab、光晕 |
| `surface / card / pop / tip / toast / code / grid` | 卡片、弹层、气泡、Toast、代码块、表格外壳 |
| `field-* / btn-* / focus-*` | 输入框、按钮、聚焦环的各种状态 |
| `chip-* / notice-* / cal-* / row-*` | 语义色（成功/警告/危险/信息）、日历、表格行 |

**Streamlit 自带组件怎么变暗？** Streamlit 的主题只在启动时从 `.streamlit/config.toml` 读一次，
运行时切不了。所以原生组件（下拉框、日期选择器、上传区、Toast、Tooltip、代码高亮、数据表工具条）
在 `_CSS_WIDGETS` 里按 `data-testid` / `role` 这类稳定钩子逐个重新上色，
再配合 `color-scheme: dark` 让浏览器原生滚动条、日期面板、自动填充也跟着变。

**唯一的例外**是 `st.data_editor`：它是 canvas 绘制的表格，CSS 变量管不到内部像素。
深色模式下只对这一块 canvas 做 `invert(1) hue-rotate(180deg)`，把它从"浅色纸片"翻成深色；
页面其它元素一律走变量，不做全局反色（K 组用例会检查这一点）。

**主题怎么记住？** 选择会写进 URL（`?theme=dark` / `?theme=light`）：

- 刷新、分享链接都能保持同一套配色，且服务端在第一帧就知道该用哪套 → 不会先闪一下浅色；
- 直接访问 `?theme=dark` 可以深链到深色版，演示时很方便；
- 首次进入且 URL 没带参数时，用 `st.context.theme` 跟随系统 / 浏览器的深浅色偏好。

> 已知差异：页面首次加载时，Streamlit 自己的骨架屏（应用挂载前的空白）仍是浏览器默认白底，
> 只有几百毫秒。要彻底消除得改 Streamlit 的 `index.html`，超出本项目的可控范围。

### 字体：思源黑体（v2.3.0 新增）

全站中文与数字统一使用 **思源黑体**（Source Han Sans / Noto Sans SC，Adobe 出品，
SIL OFL 1.1 授权，可自由商用），不再依赖系统字体 —— 这样 macOS、Windows、
手机、局域网访问的观感完全一致，不会出现「苹果上是苹方、Windows 上是雅黑」的割裂。

**字体从哪来？** 仓库里的 `static/fonts/` 是从系统已安装的思源黑体可变字体
（`NotoSansSC-VF.ttf`，wght 100–900 可变轴）子集化生成的，不是从网上下载的。
构建脚本在 `tools/build_font.py`（需 `fonttools` + `brotli`，仅生成字体时用到，运行应用不需要）。

**怎么做到只花几百 KB？** 完整字体 17.7MB 直接加载会把首屏拖垮，所以做了三层处理：

| 手段 | 效果 |
| --- | --- |
| **子集化** | 只保留应用界面 + 江大 100 条语料里实际出现的 1268 个汉字 + 拉丁标点 |
| **静态字重实例化** | 把可变字体烘焙成 400 / 700 两个静态字重，丢弃 gvar 差分数据（体积减半） |
| **unicode-range 分片** | 切成 18 片（hot / cjk-1..5 / ext-1..3），浏览器**只下载页面真正用到的片** |

首屏只拉 `hot` 片（约 190KB）；生僻字片几乎不会触发。字体文件以
`server.enableStaticServing = true` 托管在 `/app/static/fonts/`，`app.py` 里的
`_font_face_css()` 读 `manifest.json` 动态生成 `@font-face` 声明。

**emoji 怎么办？** 思源黑体不含彩色 emoji 字形，字体栈末尾挂了
`Apple Color Emoji` / `Segoe UI Emoji` / `Noto Color Emoji` —— CSS 按字符逐个回退，
所以 📅 ⏰ 🔔 这类图标在 Windows / macOS / 手机上依然是彩色的。

> 想换成别的字体：改 `tools/build_font.py` 里的 `SRC` 指向字体文件，
> 重新生成 `static/fonts/`，再改 `_TOKENS_COMMON["font-sans"]` 的字体名即可。

### 关于「⚙️ 设置与外观」面板

侧边栏顶部有一个 **⚙️ 设置与外观** 按钮，点开是统一设置面板（再点「收起设置」收起）。
以前散在侧边栏的 AI 状态和 OCR 状态都收进来了，正文区因此干净很多。

| 分区 | 内容 | 说明 |
| --- | --- | --- |
| ☀️ 界面与外观 | **明暗模式**（浅色 / 深色）、**界面字号**（小 / 标准 / 大 / 特大） | 立即生效，只影响本机显示，不改变导出文件 |
| 🤖 AI 解析 | 连接状态、模型名、**优先使用 AI 解析** 开关、如何配置 Key | 见下方说明 |
| 👁️ OCR 识别 | 本地 OCR 是否就绪、如何安装 | 见下方说明 |
| 🔔 默认提醒 | 新日程默认提前多久提醒：**可勾选 30 分钟 / 1 小时 / 2 小时 / 4 小时等，最多选 3 个** | 每个时间点在 `.ics` 里各写一条 VALARM；一条都不勾 = 不提醒 |

**AI 解析是干什么的**：把一整段口语化的话（微信群聊、语音转写、随手记）交给大模型，
让它理解出「标题 / 开始结束时间 / 地点 / 备注 / 优先级 / 循环规则」。
它的优势是懂上下文，比如「下周三下午的组会挪到周五」这种带指代和省略的句子。
没有配置 API Key 时会自动退回**本地规则引擎**——格式规整的课表、备忘录一样能解析，
而且完全离线、不联网。所以这个开关不是必须项，配置了只是「锦上添花」。

**OCR 识别是干什么的**：把课表、车票、聊天截图里的文字读出来，再送进解析引擎。
识别在本机内存里完成，图片不上传、不落盘。没装 OCR 组件时图片通道不可用，
但文本粘贴始终可用，不影响主流程。

**字号是怎么实现的**：整个界面用 `rem` 书写尺寸，改一个根字号就能等比放大按钮、表格、日历，
不是简单地把字挤大。深色模式下可编辑表格仍保持浅色底，因为它是 canvas 绘制的、
无法跟随 CSS 换色，做成「纸片卡」反而更易读。

### 关于按钮悬停提示

所有按钮 / 下拉 / 开关都带悬停说明，鼠标停一小会儿就会弹出。文案统一是
**第一行写按钮名，空一行写它做什么**，例如：

> **✨ 开始解析**
>
> 解析左侧文字和已上传的截图，把识别出的日程追加到日程表。不会覆盖已有内容；重复的条目会自动去重。

### 关于 ⚠️ 待核对标记

以下情况程序会**推测**一个合理时间，并在「状态」列标记 ⚠️：

- 只有日期没有时刻 → 默认 09:00，持续 1 小时
- 只写「3点」未说明上下午 → 按常见作息推断为 15:00
- 只写「周三」未说明本周/下周 → 取最近的该星期几
- 由本地规则引擎补充的条目（大模型遗漏时）

**推测原因会写在表格的「状态」列与导出的 `.ics` 描述中**，请核对后再使用。

### 关于时间冲突

同一自然日内两个日程的时间区间发生重叠时，两行都会被标红，并在日程表顶部列出冲突明细。
冲突**只做提示，不会自动删除**任何日程。

### 关于重复设置

**默认不循环**：每一条新录入的日程都是单次事件。只有当输入文字里出现「每周一」「每天」
「每周二、周四」「工作日」这类循环字眼时，解析器才会自动把它标成循环日程。
其余情况一律按单次处理，不会凭空产生重复项。

要修改某条日程的循环方式，到「日程表」页下方的 **重复设置** 面板：

| 控件 | 作用 |
| --- | --- |
| 选择要设置重复的日程 | 先挑一条日程，面板会自动回填它当前的设置 |
| **是否重复** 开关 | 关 = 单次日程；开 = 按下方频率重复 |
| **重复频率** | 每周重复 / 每两周重复 / 每天重复 |
| **循环开始日期** | 循环的第 1 次落在哪天；改它会把整条日程一起平移（时分与时长不变），星期几也会跟着重算 |
| **重复次数**（➖ 数字 ➕） | 1~60 次，含第一次；停止点由次数决定 |
| **✅ 应用 / 🚫 取消** | 写入或清除该日程的重复规则 |

**次数是真实生效的**：程序会把次数写进标准 RRULE 的 `COUNT` 属性
（如 `FREQ=WEEKLY;BYDAY=WE;COUNT=10`），导入手机 / Outlook 后，日历会在第 10 次之后自动停止，
不会变成「永久重复」。

几点设计细节：

- **切换频率不会改变星期几**。例如「每周一三五」的日程改成「每两周重复」，结果是
  `FREQ=WEEKLY;INTERVAL=2;BYDAY=MO,WE,FR` —— 仍然是一、三、五，只是隔周。
- **改循环开始日期会同步改星期几**。把一条「每周一」的课改到周五开始，规则会跟着变成
  `BYDAY=FR`，不会出现「写着周五开始、却每周一重复」的矛盾。
- **表格的「重复」列只读**，显示成「每两周的周三 · 共 10 次」这样的中文，避免手误改坏 RRULE。
  真要手写规则，面板里有「高级：直接编辑重复规则（RRULE）」。
- **没有单独设次数的循环日程**（例如直接解析「每周四上课」得到的）在入库时统一补上默认
  `COUNT=16`（约一学期），保证导出的 .ics 一定有结束条件。页面上不再有全局「兜底周数」开关，
  次数只在日程表里逐条调整。
- 重复日程的**冲突检测只检查首次实例**，不会展开未来所有实例（见「已知限制」）。

### 关于月历视图

「日程表」页顶部有一块月历，行为对齐手机自带日历：

- 顶部 `‹` / `›` 翻月（跨年自动进位），`↩ 回到今天` 一键跳回当月并选中今天
- 周一起始的 7 列网格，有安排的日期在日号后带一个中点 `·`，鼠标悬停可看当天条数
- 点某个日期，右侧立刻列出当天全部安排——**循环日程也会按规则命中**，
  不只是首次实例；冲突标红、待核对标黄
- 底部一行汇总本月总安排数与循环日程条数

### 关键技术决策

| 决策 | 原因 |
| --- | --- |
| **固定 UTC+8 偏移**而非 `zoneinfo` | 中国无夏令时，固定偏移精确；避免 Windows 缺 `tzdata` 时报 `ZoneInfoNotFoundError` |
| **ICS 用 UTC 时间戳**（`DTSTART:...Z`） | 绝对时刻，任何日历客户端都能正确换算本地时间，无需 `VTIMEZONE` |
| **ICS 按 UTF-8 字节折行 75 列** | RFC 5545 强制要求；按字符数折行会让中文标题在 Outlook 中解析失败 |
| **规则引擎 + 大模型双路融合** | 保证无网络/无 Key 时仍可用，且能用规则结果校正模型输出 |
| **`st.session_state` 存全部数据** | 满足"不落库、不落盘"的隐私要求，刷新即销毁 |
| **`on_click` 回调修改输入框** | Streamlit 不允许在 widget 实例化后直接改其 `session_state` |
| **内容指纹判断编辑** | 避免 `data_editor` 同步 → `rerun` → 再同步的无限循环 |
| **OCR 前缩放到 2400px** | 大图直接跑 OCR 极慢；等比缩放对识别率几乎无影响 |

## 🔒 隐私与合规

- **不落库**：无数据库、无 ORM、无 SQL，所有数据仅存于 `st.session_state`（浏览器会话内存）。
- **不落盘**：不上传文件到磁盘，不写日志文件，不缓存图片。
- **图片不出本机**：OCR 使用本地 `rapidocr` 模型推理，原图不发送到任何服务器。
- **仅文本出网**：仅当配置了大模型时，**识别出的文字**会发送至该模型服务用于解析。
- **密钥安全**：可从侧边栏「🤖 AI 接口」弹窗填写（只存页面内存，刷新即失效），或从环境变量 / Streamlit Secrets 读取；不写入代码、不写入日志、不回显完整密钥。
- **免责声明**：页面底部常驻，明确解析结果仅供参考、使用风险自负。

## ⚠️ 已知限制

1. **手写体与艺术字识别率低**：OCR 针对印刷体优化，手写课表建议手动录入。
2. **复杂表格截图**：多列课表（周一~周日横向排布）可能被解析为单列，建议按行截图。
3. **极度口语化的表达**：如「下周找个时间聚一下」，规则引擎无法解析，需配置大模型。
4. **农历日期不支持**：仅识别公历。
5. **循环日程的冲突检测**：只检查已录入的首次实例，不会展开未来所有实例做冲突检查。
6. **单次上限**：文本 20000 字、图片 3 张 × 10MB、单次解析最多 60 条（防止异常输出撑爆页面）。
7. **时区**：固定按 UTC+8 处理，海外用户需自行调整 `CN_TZ` 常量。
8. **首次 OCR 推理较慢**：需要加载约 15MB 模型，首次约 3~5 秒；之后由缓存加速。
   **建议比赛前先上传一张图预热。**
9. **数据不持久化**：刷新页面即清空（这是隐私设计的一部分），演示完请及时导出 `.ics`。
